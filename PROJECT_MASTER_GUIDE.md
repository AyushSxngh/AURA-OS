## 1. EXECUTIVE SUMMARY & CORE OBJECTIVES

### 1.1 Project Philosophy
Standard Android Virtual Devices (AVDs) run on stock AOSP images with glaring emulator artifacts:
- Generic identifiers (`sdk_gphone64_arm64`, `goldfish`, `ranchu`, `AOSP`).
- Synthetic networking: SSID `AndroidWifi`, BSSID `02:00:00:00:00:00`, dead gateway `10.0.2.2`, guest IP `10.0.2.16`.
- Dummy battery state: stuck at 100% AC plugged, linear or infinite battery health, 1000 mAh capacity, zero usage history.
- Telephony giveaways: default US number `+1 555-521-5554` or `+1 555-123-4567`, carrier `Android`, MCC/MNC `310260`.
- Camera emulation: artificial checkerboard animations, fixed resolution, or laggy desktop webcam feeds.

This project transforms an ARM64 Android Virtual Device running on Apple Silicon into a **mathematically, cryptographically, and behaviorally indistinguishable Samsung Galaxy S24 Ultra (`SM-S928B`)**.

### 1.2 Key Architectural Feats
1. **Low-Level QEMU Binary Dispatcher**: An in-line C proxy (`qemu_dispatcher.c`) replaces the Android SDK's `qemu-system-aarch64` binary. It intercepts startup parameters, enforces hardware limits (12 GB RAM, 8 cores), generates Luhn-compliant Samsung TAC IMEIs, hex-patches binary offsets in real-time, and injects dynamic libraries via `DYLD_INSERT_LIBRARIES`.
2. **Byte-Exact Image Patching**: System partitions (`system.img`, `vendor.img`, `ramdisk.img`) and `build.prop` files are binary-patched without modifying total byte counts or unmounting, utilizing comment padding (`#===`) and exact-length string substitutions.
3. **In-Memory Power Profile Deflation**: `framework-res.apk` and its overlay APK inside raw `system.img` are decompressed, patched to 5000 mAh with 150-unit screen attribution, re-compressed with ZLIB Level 9 to match exact deflate lengths, and written back with updated CRC32 checksums.
4. **Live Physical Wi-Fi Mirroring**: A continuous background daemon (`sec_wifi_service.py`) mirrors the host MacBook's actual Wi-Fi SSID, router BSSID, subnet mask, real gateway (`10.11.13.1`), DNS servers, and assigned IP (`10.11.12.92`), eliminating `AndroidWifi` and `10.0.2.2` at the kernel SLIRP level.
5. **Realistic Battery Simulation**: A daemon (`sec_battery_service.py`) runs a true Li-ion Open Circuit Voltage (OCV) discharge curve (3550 mV to 4350 mV), temperature thermals (29°C to 37.5°C), dynamic capacity scaling in microampere-hours ($\mu\text{Ah}$), and a historical usage seeder that attributes power to real apps (Chrome, YouTube, WhatsApp).
6. **Indian UICC / SIM Emulation**: Low-level modem simulator profiles (`iccprofile_for_sim0.xml`) are encoded with 3GPP BCD data to present an authentic Indian mobile number (`+91 93152 94420`) and Jio 4G carrier network.
7. **Lock-Free Camera Injection**: An Objective-C dynamic library (`libsec_camera_provider.dylib`) hooks macOS AVFoundation capture delegates in QEMU, reading triple-buffered shared memory (`/tmp/sec_cam_shm`) generated by a real-time DeepFake streaming engine (`http://127.0.0.1:8080`).

## 4. LOW-LEVEL BINARY INTERCEPTION & QEMU DISPATCHER

### 4.1 Architecture of `tools/qemu_dispatcher.c`
When Android Studio or the CLI executes `emulator`, the frontend binary launches `qemu-system-aarch64`. To achieve total hardware spoofing, `qemu-system-aarch64` is replaced with `tools/qemu_dispatcher` (with the original binary preserved as `qemu-system-aarch64.orig`).

```text

    ├── 1. Injects DYLD_INSERT_LIBRARIES = libsec_camera_provider.dylib
```

```c
            n *= 2;
            if (n > 9) n -= 9;

        total += n;

    return (10 - (total % 10)) % 10;
```

## 5. BYTE-EXACT SYSTEM IMAGE & PARTITION PATCHING

### 5.1 The Byte Preservation Constraint
Modern Android system images (`system.img`, `vendor.img`) utilize ext4 filesystems with dm-verity hash trees and strict superblock inode mappings. Any byte length modification breaks partition alignment or fails QEMU initialization.

To bypass this without compiling Android from source:
1. `tools/patch_device_properties.py` searches for 5-line property blocks across all partitions (`system`, `system_ext`, `vendor`, `odm`, `product`).
2. The replacement string is formatted, and the difference in byte length is padded using comment characters (`#=============\n`):
```python
def patch_partition_block(part, orig_block):
    orig_len = len(orig_block)
    lines = [
        f"ro.product.{part}.brand=samsung",
        f"ro.product.{part}.device=e3q",
        f"ro.product.{part}.manufacturer=Samsung",
        f"ro.product.{part}.model=SM-S928B",
        f"ro.product.{part}.name=e3qxeea",
    ]
    new_text = "\n".join(lines) + "\n"
    diff = orig_len - len(new_text)
    if diff > 0:
        pad = "#" + ("=" * (diff - 2)) + "\n"
        new_text += pad
    assert len(new_text) == orig_len
    return new_text.encode("utf-8")
```

### 5.2 In-Place Power Profile Patching (`patch_power_profile.py`)
Android Settings derives battery capacity and usage attribution from `res/xml/power_profile.xml` inside `framework-res.apk` and `framework-res__auto_generated_rro_product.apk`.

Stock values:
- `battery.capacity` = `1000` mAh
- `screen.full` = `0.1`

Patched values:
- `battery.capacity` = `5000` mAh
- `screen.full` = `150`

**Mechanism:**
1. Scans raw `system.img` for the ZIP local header (`PK\x03\x04`) at known offsets (`2123407360` for RRO, `384630784` for framework-res).
2. Inflates the raw deflate stream in memory.
3. Performs string pool substitution (`\x04\x041000\x00` $\rightarrow$ `\x04\x045000\x00`).
4. Re-compresses with `zlib.compress(..., 9)` ensuring the compressed length matches the exact byte count down to the bit.
5. Recalculates and updates the CRC32 checksum in both the local file header and central directory records.

## 8. TELEPHONY, UICC SIM PROFILE & INDIAN NUMBER STACK

### 8.1 3GPP BCD Phone Number Encoding
Android's `SubscriptionController` reads SIM phone numbers from `EF_MSISDN` (ID `6F40`) and `EF_MBDN` (ID `6FC7`) in the UICC filesystem. Numbers are stored as packed Binary Coded Decimal (BCD) with nibble swapping:

#### Encoding Formula:
1. Strip leading `+`.
2. Pad with `F` if the digit count is odd.
3. Swap adjacent nibbles (e.g. `91` $\rightarrow$ `19`).
4. Prepend Type of Number (TON/NPI): `91` indicates International ISDN format.
5. Prepend length in bytes (BCD digits + 1 byte for TON).
6. Right-pad with `FF` to match field width (14 bytes / 28 hex characters).

#### Encoding Example for `+91 93152 94420`:
- Digits: `91 93 15 29 44 20` (12 digits)
- Nibble-swapped pairs: `19 39 51 92 44 02`
- TON/NPI: `91`
- Length byte: `07` (6 bytes digits + 1 byte TON)
- Result: `07 91 19 39 51 92 44 02 FF FF FF FF FF FF`
- Final Hex: `0791193951924402FFFFFFFFFFFF`

### 8.2 UICC Profile Files
The encoded MSISDN is placed in the following files:
- `~/.android/avd/AURA_OS_ARM64.avd/modem_simulator/iccprofile_for_sim0.xml`
- `~/.android/avd/AURA_OS_ARM64.avd/modem_simulator/iccprofile_for_carrierapitests.xml`
- `~/Library/Android/sdk/system-images/android-34/.../modem_simulator/iccprofile_for_sim0.xml`
- `~/Library/Android/sdk/system-images/android-34/.../modem_simulator/iccprofile_for_carrierapitests.xml`

```xml
    <SIMIO cmd="B2" p1="1" p2="4" p3="1C" data="">144,0,00000000000000000000000000000791193951924402FFFFFFFFFFFF</SIMIO>
```

### 8.3 The ICCID Cache-Busting Mechanism
**Critical Finding**: Android's `SubscriptionController` caches SIM records by ICCID in `/data/user_de/0/com.android.providers.telephony/databases/telephony.db`. If the ICCID is unchanged across boots, Android reuses the cached record and skips reading `EF_MSISDN`.

**Solution**: Whenever changing phone numbers, increment the ICCID:
- Previous ICCID: `89918400000000000020` (Hex BCD: `98194800000000000002`)
- Updated ICCID: `89918400000000000030` (Hex BCD: `98194800000000000003`)
- Android detects a newly inserted physical SIM card, assigns a fresh subscription ID (`subId=3`), and populates `+91 93152 94420`.
- All XML files are set to read-only (`chmod 444`) to block QEMU in-memory flush overwrites.

```text
[ DeepFake Realtime Engine ] (Python / PyTorch on port 8080)
           │
           │ (Writes raw BGR24 / BGRA32 frames)

```

### 9.2 Triple-Buffered Shared Memory Header (`AuraCamHeader`)
Defined in `tools/sec_camera_provider.m` and `DeepFake_realtime/stream/stream_server.py`:
```c
struct __attribute__((packed)) AuraCamHeader {
    uint32_t magic;                 // 0x41555241 ('AURA')
    uint32_t version;               // 3 (Triple-buffered)
    uint32_t width;                 // 1920
    uint32_t height;                // 1080
    uint32_t stride;                // bytes per row
    uint32_t format;                // 0 = BGR24, 1 = BGRA32
    uint64_t timestamp_ms;          // Epoch timestamp
    uint32_t data_size;             // Payload byte size
    uint32_t frame_seq;             // Monotonic sequence number
    volatile uint32_t latest_ready_buf;     // Buffer index: 0, 1, or 2
    volatile uint32_t consumer_reading_buf; // Buffer currently being read
    uint32_t buffer_stride;         // 1920 * 1080 * 4
    uint32_t num_buffers;           // 3
    uint8_t  reserved[8];
};
```

### 9.3 Key Performance Features
1. **Lock-Free Concurrency**: Producer writes to `(latest_ready_buf + 1) % 3` while consumer reads from `latest_ready_buf`, eliminating lock contention and frame tearing.
2. **Static Holdover Buffer**: If the deepfake engine pauses, the hook repeats the last valid frame from static memory rather than falling back to the physical Mac webcam, preventing webcam leakage.
3. **Precomputed Coordinate LUT**: Fast bilinear resizing (<2 ms per frame) converts native deepfake dimensions (e.g. 512x512) to Android Camera HAL capture format (1920x1080 / 1280x720).
